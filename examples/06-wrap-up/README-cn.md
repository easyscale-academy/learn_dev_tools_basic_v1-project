## 4. 回顾: 这门课其实在讲什么

这门课表面上是四个独立的 Task, 装 mise, 装 Mac 三件套, 学 VS Code, 认识 coding agent, 但其实自始至终都在讲同一件事: 怎么给 coding agent 搭一个能真正干活的舞台.

mise 解决的是工具版本管理这个基础设施问题, 让你不用在五六个各自为政的版本管理器之间疲于奔命. Mac 三件套装的三样东西, VS Code, Terminal, GitHub Desktop, 分别对应舞台的三个部分: 看得见改动, 能跑命令, 能撤销. VS Code 那一课教的复制路径和集成终端, 是人和 AI 之间沟通的具体语法. 到了认识 coding agent 那一课, 前面三课攒的东西才连成一条线, 你现在有了一整套能让 AI 真正动手干活, 而不是只能聊天的环境.

如果说这门课有一个骨架, 那就是这句话: coding agent 能不能干活, 取决于它有没有一个能干活的环境. 工具, 终端, 版本控制, 一样都不能少.

一开始你可能觉得这几件事没什么关系, mise 是装工具的, Terminal 是敲命令的, GitHub Desktop 是管代码的, VS Code 是编辑器. 学完回头看, 它们其实是同一套舞台的四根柱子, 缺一根, coding agent 就少一分能干活的空间.

## 5. 你现在能做什么

- 在 Mac 或 GitHub Codespace 上, 从零装好一整套开发环境, 包括 mise, VS Code, Terminal, GitHub Desktop
- 用 VS Code 打开任意一个项目文件夹, 找到文件, 复制它的完整路径, 打开集成终端
- 有一个能用的 AI 产品账号, 并会基本操作至少一个 coding agent
- 说清楚 coding agent 和聊天机器人的本质区别, 以及为什么前面那些工具都是为它准备的
- 遇到改坏的情况, 知道用 GitHub Desktop 的 History 一键退回去

## 6. 练习: 跑一遍完整的工作流

### 练习 1: 从打开项目到让 AI 动手改一个字

**目标:** 把这门课学的几件事串成一次真实的操作, 而不是分开验证.

**怎么做:**

1. 用 GitHub Desktop 打开一个你已经 clone 到本地的项目 (或者现场 clone 一个)
2. 用 VS Code 打开这个项目文件夹
3. 找一个文本文件, 右键 Copy Path
4. 打开你的 coding agent, 把路径粘贴给它, 让它帮你在这个文件里加一句无关紧要的话, 比如加一行注释
5. 回到 GitHub Desktop, 看看它有没有记录下这次改动, 如果不满意, 试着用 History 退回去

**你会观察到:**

从打开项目到 AI 完成修改, 整个过程不需要你自己动手写一个字, 你做的只是指路和检查.

> **关键洞见:** 这就是这门课想让你养成的工作方式, 人负责说清楚要什么和检查结果, AI 负责具体动手.

## 7. 继续往前走的几个方向

如果还想更进一步, 这几个方向都值得深挖. 下面只给关键字和一句话话题, 具体怎么学, 交给你自己去查, 或者直接喂给 AI.

- mise 的进阶用法: 搜索关键字 `mise tasks`, `mise.toml`. 可以问 AI: 我已经会基本的 mise use 命令了, 想了解 mise.toml 里的 tasks 怎么定义和运行, 能不能举一两个贴近日常开发的例子
- Terminal 的进阶配置: 搜索关键字 `dotfiles`, `oh-my-zsh`. 可以问 AI: 我想把自己的 Terminal 配置整理成一份 dotfiles, 方便换电脑时快速恢复, 应该怎么开始
- Git 和 GitHub 的协作方式: 搜索关键字 `git branching workflow`, `GitHub pull request`. 可以问 AI: 我现在只用 GitHub Desktop 的基本功能, 想搞懂 branch 和 pull request 是怎么协作的
- coding agent 的进阶能力: 搜索关键字 `Claude Code MCP`, `agent skills`. 可以问 AI: 我想让我的 coding agent 具备更多能力, 比如连接外部工具或者拥有可复用的技能, 该从哪里学起

## 8. 导师寄语

**为什么这个练习重要:**

很多课程学完就学完了, 知识散落在各个章节里, 没人帮你串起来. 这门课想让你带走的不是四个独立的技能点, 而是一套完整的心智模型: 先给 AI 搭好能干活的舞台, 再放手让它干活, 自己负责说清楚要什么, 检查结果对不对.

**关键洞见:**

- 工具本身不难, 难的是知道为什么要用它, 以及它在整套工作流里扮演什么角色
- 遇到教程没教的地方, 带着具体场景去问 AI, 比等一份写好的教程更快, 也更贴合你的实际需要

**下一步:**

去找一个你真正想做的小项目, 把这套工作流跑起来. 不需要等到全部学会才开始, 这门课教的这几样东西已经够你上路了.

## 9. 速查

**这门课装好的整套工具:**

- mise: 统一管理开发工具版本
- VS Code: 打开项目, 复制路径, 打开集成终端
- Terminal (或 Ghostty): 跑命令, 也是 coding agent 干活的地方
- GitHub Desktop: 提交改动, 也是你的后悔药

**核心工作流:**

打开项目, 复制路径, 告诉 AI 要改什么, 检查结果, 用 GitHub Desktop 保存或者退回.
